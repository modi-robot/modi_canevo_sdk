# CanEvo CSP 硬实时系统配置方案

本文整理当前 ARM/NIIC 环境的配置思路，并给出迁移到 x86 工控机 PREEMPT_RT 内核时的推荐配置。目标是让 CSP 控制循环尽量稳定地按同步周期发送 SYNC/PDO，避免从站因同步抖动切换到 PP。

## 1. 背景和约束

CanEvo CSP 模式对主站同步周期要求很高：

- 连续 3 次同步周期偏差超过 ±20 us，关节可能自动切换到 PP。
- 单次同步周期偏差超过 ±50 us，关节可能自动切换到 PP。

因此要同时关注两件事：

- 用户态实时线程是否准时醒来。
- CAN 帧真正出现在总线上的时间是否稳定。

实时内核只能保证第一层。第二层还取决于 CAN 控制器、驱动、IRQ 亲和性、发送队列、总线负载和适配器硬件。USB 转 CAN 通常不适合这类 ±20 us/±50 us 级同步场景，建议优先使用板载 CAN、PCIe CAN、SPI CAN 或工业 CAN-FD 卡。

## 2. 当前 ARM/NIIC 环境参考

当前机器信息：

```bash
Architecture: aarch64
CPU(s): 8
Model name: Cortex-A78AE
On-line CPU(s): 0-7
```

当前启动参数：

```bash
isolcpus=1 nohz_full=1 rcu_nocbs=1 irqaffinity=0,2,3,4,5,6,7 nmi_watchdog=0
```

实际隔离状态：

```bash
cat /sys/devices/system/cpu/isolated
# 1

cat /sys/devices/system/cpu/nohz_full
# 1
```

当前线程分配策略：

| 角色 | CPU | 说明 |
| --- | --- | --- |
| CSP 实时线程 | CPU1 | 隔离核，`SCHED_FIFO 99` |
| SDK Rx 线程 | CPU3 | 非隔离核，`SCHED_FIFO 90` |
| 系统 IRQ 默认 | CPU0,2-7 | 通过 `irqaffinity` 排除 CPU1 |
| can0 IRQ | CPU0,2-7 | 当前 `/proc/irq/202/smp_affinity_list` 为 `0,2-7` |

当前代码侧使用 NIIC/qiuniu：

- `example_single_joint_csp`
- `example_multi_joints_csp`
- `example_single_joint_rt_thread`

关键实时调用通过 `__RT(...)` 包装：

```cpp
__RT(clock_gettime(...));
__RT(clock_nanosleep(...));
__RT(pthread_create(...));
__RT(pthread_join(...));
```

在 x86 PREEMPT_RT 工控机上通常没有 NIIC/qiuniu，`CANEVO_HAVE_NECRO=0` 时 `__RT(expr)` 会退化为普通 POSIX 调用；实时性主要依赖 PREEMPT_RT、CPU 隔离和 IRQ 调优。

## 3. x86 工控机推荐硬件

优先级从高到低：

1. 主板/工控机原生 CAN-FD 控制器。
2. PCIe CAN-FD 卡。
3. SPI CAN-FD 控制器，前提是 SPI 控制器和驱动实时性足够好。
4. USB-CAN，仅建议用于 SDO、调试、低实时要求模式，不建议用于 CSP。

如果必须用 USB-CAN：

- 不要接 USB hub。
- 关闭 USB autosuspend。
- 尽量固定 xHCI IRQ 到非实时核。
- 降低发送队列长度。
- 用示波器或逻辑分析仪验证 CAN_H/CAN_L 上 SYNC 帧间隔。

但 USB 传输调度和适配器固件队列通常会带来不可控抖动，很难保证 ±20 us/±50 us。

## 5. CPU 规划

建议至少 4 核：

| 角色 | 推荐 CPU | 说明 |
| --- | --- | --- |
| 实时控制线程 | CPU2 | 独占隔离核 |
| CAN IRQ / CAN Rx 线程 | CPU3 | 与实时线程分开，避免抢占 |
| 系统普通任务 | CPU0,1 | systemd、桌面、SSH、日志等 |

如果工控机有 8 核，可以采用：

| 角色 | 推荐 CPU |
| --- | --- |
| 实时控制线程 | CPU2 |
| CAN IRQ / SDK Rx | CPU3 |
| 系统普通任务 | CPU0,1,4,5,6,7 |

注意：不要把实时线程和 CAN IRQ/Rx 线程放在同一个 CPU 上，除非你明确需要缩短跨核路径并已经测过效果。默认推荐分开，因为 CAN IRQ/Rx 可能打断控制线程。

## 8. CPU 频率和省电设置

建议关闭动态调频和深 C-state。

临时设置 governor：

```bash
sudo cpupower frequency-set -g performance
```

如果没有 `cpupower`：

```bash
sudo apt install -y linux-tools-$(uname -r)
```

确认：

```bash
cat /sys/devices/system/cpu/cpufreq/policy*/scaling_governor
```

期望：

```text
performance
```

BIOS/UEFI 建议：

- Disable C-States 或限制到 C1。
- Disable Intel SpeedStep / Speed Shift，或固定 Performance 模式。
- Disable Turbo Boost，优先稳定延迟而不是峰值性能。
- Disable Hyper-Threading，或不要把实时线程放在 SMT sibling 上。
- Disable ASPM/PCIe power saving。

## 9. CAN-FD 配置

配置 CAN-FD：

```bash
sudo ip link set can0 down 2>/dev/null || true
sudo ip link set can0 type can bitrate 1000000 dbitrate 5000000 fd on
sudo ip link set can0 txqueuelen 1
sudo ip link set can0 up
```

查看状态：

```bash
ip -details link show can0
```

降低 `txqueuelen` 可以减少内核队列积压，让发送时间更接近实时线程调度点。多关节报文较多时可以对比 `txqueuelen 1`、`2`、`4` 的总线实际抖动，最终以示波器/逻辑分析仪结果为准。

## 10. CAN IRQ 亲和性

找到 CAN IRQ：

```bash
grep -n "can0\|can\|kcan\|pcan\|mttcan" /proc/interrupts
```

假设 IRQ 号是 `202`，把它放到 CPU3：

```bash
echo 3 | sudo tee /proc/irq/202/smp_affinity_list
```

确认：

```bash
cat /proc/irq/202/smp_affinity_list
```

建议：

- 实时控制线程在 CPU2。
- CAN IRQ 在 CPU3。
- SDK Rx 线程也在 CPU3，或者放在另一个非隔离但低干扰 CPU。
- 不要让其他 IRQ 进入 CPU2。

可以把大多数 IRQ 排除出 CPU2：

```bash
for irq in /proc/irq/[0-9]*; do
  echo 0,1,3 | sudo tee "$irq/smp_affinity_list" >/dev/null 2>&1 || true
done
```

然后单独确认 CAN IRQ：

```bash
grep -n "can0\|can\|kcan\|pcan" /proc/interrupts
```

## 11. 应用线程配置

当前 CSP 示例配置思路：

```cpp
// 实时控制线程
SCHED_FIFO 99
CPU affinity = isolated CPU

// SDK Rx 线程
SCHED_FIFO 90
CPU affinity = non-isolated CPU
```

x86 工控机示例：

```cpp
int cpu = 2;                      // 实时线程绑定 CPU2
task_config.cpu_affinity = 3;     // SDK Rx 线程绑定 CPU3
task_config.sched_priority = 90;
```

当前 ARM 示例里使用的是 CPU1，因为当前设备实际隔离核是 CPU1。迁移到 x86 后要按 `/sys/devices/system/cpu/isolated` 的结果同步修改示例里的 CPU 编号。

运行时应确认打印：

```text
NIIC hard realtime: OFF (POSIX)   # x86 PREEMPT_RT 常见情况
✓ 实时线程绑定 CPU2
✓ SDK Rx 线程绑定 CPU3, 优先级 90
```

如果 x86 机器也安装了 NIIC/Necro，则可能显示：

```text
NIIC hard realtime: ON (__RT -> qiuniu)
```

## 12. 验证实时线程抖动

先测纯实时线程，不接 CAN：

```bash
cd /home/niic/Desktop/canevo_sdk_x86/build/example
sudo ./example_single_joint_rt_thread
```

关注输出：

```text
最大绝对周期抖动
平均绝对周期抖动
|周期抖动| > 20 us
|周期抖动| > 50 us
```

如果纯线程已经经常超过 50 us，应先调内核、CPU 隔离、IRQ 和 BIOS。

也可以用 `cyclictest`：

```bash
sudo cyclictest -m -Sp99 -i5000 -a2 -h400 -l100000
```

含义：

- `-a2`：绑定 CPU2。
- `-i5000`：5 ms 周期。
- `-p99`：实时优先级 99。

## 13. 验证 CAN 总线实际抖动

软件时间戳只能看到主机侧，不等于从站看到的总线时间。CSP 最终要看 CAN 总线上的 SOF 间隔。

推荐验证方式：

1. 用示波器或逻辑分析仪接 CAN_H/CAN_L，解码 SYNC 帧。
2. 统计相邻 SYNC 帧 SOF 间隔。
3. 检查是否有连续 3 次超过 ±20 us，或单次超过 ±50 us。

辅助软件观测：

```bash
candump -tz can0
```

注意：`candump` 时间戳包含驱动和内核路径影响，不能替代总线物理层测量。

## 14. USB-CAN 风险

如果使用 USB 转 CAN，即使实时线程非常稳定，从站收到报文仍可能抖动很大。典型路径：

```text
实时线程 -> SocketCAN -> USB host/xHCI -> USB 调度 -> USB-CAN 固件队列 -> CAN 控制器 -> CAN 总线
```

风险来源：

- USB high-speed microframe 为 125 us 量级。
- USB-CAN 固件可能批量发送或内部排队。
- xHCI IRQ、USB autosuspend、hub、其他 USB 设备都会引入延迟。
- SocketCAN 发送时间不等于总线 SOF 时间。

结论：

- CSP 不建议使用 USB-CAN。
- SDO、PP、低频调试可以使用 USB-CAN。
- 若必须用 USB-CAN，需要接受无法稳定满足 ±20 us/±50 us 的风险。

## 15. 推荐启动脚本

可以创建 `script/setup_rt_can.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail

RT_CPU=2
CAN_CPU=3
SYSTEM_CPUS=0,1,3
CAN_IF=can0

sudo cpupower frequency-set -g performance || true

sudo ip link set "${CAN_IF}" down 2>/dev/null || true
sudo ip link set "${CAN_IF}" type can bitrate 1000000 dbitrate 5000000 fd on
sudo ip link set "${CAN_IF}" txqueuelen 1
sudo ip link set "${CAN_IF}" up

for irq in /proc/irq/[0-9]*; do
  echo "${SYSTEM_CPUS}" | sudo tee "${irq}/smp_affinity_list" >/dev/null 2>&1 || true
done

CAN_IRQS=$(grep -n "${CAN_IF}" /proc/interrupts | cut -d: -f1 | tr -d ' ')
for irq in ${CAN_IRQS}; do
  echo "${CAN_CPU}" | sudo tee "/proc/irq/${irq}/smp_affinity_list"
done

echo "isolated CPUs: $(cat /sys/devices/system/cpu/isolated)"
echo "nohz_full CPUs: $(cat /sys/devices/system/cpu/nohz_full)"
ip -details link show "${CAN_IF}"
grep -n "${CAN_IF}" /proc/interrupts || true
```

按实际 CPU 和 CAN 驱动名称修改后使用：

```bash
chmod +x script/setup_rt_can.sh
./script/setup_rt_can.sh
```

## 16. 故障排查清单

### 线程抖动大

- `uname -a` 是否为 PREEMPT_RT。
- 实时线程是否绑定隔离核。
- `mlockall()` 是否成功。
- 是否用 root 或具备 `CAP_SYS_NICE`。
- CPU governor 是否为 performance。
- BIOS 是否关闭深 C-state、Turbo、SMT。
- 隔离核是否仍有 IRQ。

### 线程稳定但从站仍切 PP

- 是否使用 USB-CAN。
- CAN IRQ 是否和实时线程抢同一个核。
- CAN 发送队列是否过长。
- 总线负载是否过高。
- 多关节 PDO 数量是否导致总线占用接近周期上限。
- 是否在实时循环中做了 SDO、日志打印、动态分配、阻塞调用。
- 是否用示波器确认 SYNC 帧 SOF 间隔。

### 多关节比单关节更容易切 PP

- 多关节每周期 CAN 帧更多，总线占用更高。
- RxPDO 逐个发送会增加周期内帧尾部延迟。
- 检查 CAN-FD 数据段波特率是否为 5 Mbps。
- 降低关节数量或周期频率做 A/B 测试。
- 用示波器观察每周期第一帧 SYNC 和后续 RxPDO 的相对时间。

## 17. 推荐迁移步骤

1. 安装并启动 x86 PREEMPT_RT 内核。
2. 选择实时 CPU 和 CAN IRQ CPU。
3. 配置 GRUB：`isolcpus`、`nohz_full`、`rcu_nocbs`、`irqaffinity`。
4. 配置 systemd `CPUAffinity`，排除实时 CPU。
5. BIOS 关闭省电和深 C-state。
6. 配置 CAN-FD 和 IRQ 亲和性。
7. 先运行 `example_single_joint_rt_thread` 测纯线程抖动。
8. 再运行单关节 CSP。
9. 最后运行多关节 CSP。
10. 用示波器或逻辑分析仪验证 CAN 总线 SYNC 周期。

## 18. 目标状态

理想运行状态：

- 实时线程 `SCHED_FIFO 99`，独占隔离核。
- SDK Rx 线程 `SCHED_FIFO 90`，非隔离核。
- CAN IRQ 固定到非隔离核。
- 系统普通任务不进入隔离核。
- CPU 固定 performance，关闭深度省电。
- 使用非 USB 的 CAN-FD 控制器。
- 总线物理层 SYNC 周期满足 CSP 阈值。
