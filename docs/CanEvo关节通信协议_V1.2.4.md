#                                                         CanEvo关节通信协议

CanEvo关节通信协议是专为机器人关节设计的基于CAN FD的通信标准，旨在实现： 

- 高实时性；
- 简化控制接口；
- 兼容传统CAN设备；
- 丰富的状态反馈；

 **适用场景**：机器人关节控制，机械臂运动控制，工业自动化设备，需要高精度位置/速度/力矩控制的场合。

#### 术语

> **node：**节点——一个CAN FD通信终端称为节点，它可以是关节、工具端等<br>
> **node\_id：**节点ID——1\~62，广播节点ID为 0x3F（63）<br>
> **cob\_id：**通信对象标识符——仲裁域 <br>
> **function_code：**功能码——定义通讯帧的功能 <br>
> **RxPDO：**接收过程数据——节点接收到来自于主站的过程数据 <br>
> **TxPDO：** 发送过程数据——节点向主站发送的过程数据 <br>
> **主站：**X86工控机或者是ARM工控板，也可以是基于MCU的嵌入式控制板 <br>
> **Index：**协议表索引<br>**Subindex：**协议表子索引 



# 1 通讯模式

## 1.2 应答式SDO

主站和节点之间采用问答方式通信，即主站发出指令包，节点返回应答包。

一个CAN总线网络中允许有多个节点，所以每个节点都分配有一个ID号。主站发出的控制指令中包含ID信息，只有匹配上ID号的节点才能完整接收这条指令，并返回应答信息。

### 1.2.1 应答式命令

应答式报文的第一个字节是命令字，定义应答式报文功能，如读指令、写指令相关的控制指令等，命令字的格式如下：

​                                                                      **【表 4】 命令字**

| bit7                         | bit6 | bit5 | bit4~bit0 |
| ---------------------------- | ---- | ---- | --------- |
| 错误标识 （1：错误 0：正常） | 保留 | 保留 | 指令      |

  命令字中的指令如下：

​                                                                      **【表 5】命令字列表**

| 指令   | 功能               | 值   | 数据长度 |
| ------ | ------------------ | ---- | -------- |
| CMD_RD | 查询协议表里的数据 | 0x01 | 不小于3  |
| CMD_WR | 往协议表里写入数据 | 0x02 | 不小于3  |

### 1.2.2 应答式读

应答式读用于主站读取节点协议表中的数据，由读指令、读应答（正常）、读应答（异常）组成，详细报文格式如下：

​                                                                      **【表 6】 对象字典读**

| 类型           | **仲裁域**       | **控制域** |      |      |      | **数据域**    |       |          |                        |
| -------------- | ---------------- | ---------- | ---- | ---- | ---- | ------------- | ----- | -------- | ---------------------- |
|                | STID             | RTR        | IDE  | R0   | DLC  | D0            | D1    | D2       | D3~D6                  |
| 读指令         | 0x780 + node\_id | 0          | 0    | 0    | 3    | CMD_RD        | Index | SubIndex | --                     |
| 读应答（正常） | 0x7C0 + node\_id | 0          | 0    | 0    | 4~7  | CMD_RD        | Index | SubIndex | 索引映射的数据         |
| 读应答（异常） | 0x7C0 + node\_id | 0          | 0    | 0    | 5    | 0x80 + CMD_RD | Index | SubIndex | 应答式故障码（2bytes） |

节点返回的指令中，读取正常的情况下，数据域第一个字节为CMD_RD (0x01)，第二个字节为索引值，第三个字节为子索引，之后的字节长度根据索引+子索引对应的对象数据类型确定。

当出现读错误时，数据域第一个字节是读命令字0x80 + CMD_RD  (0x81)，第二个和第三个字节是索引值+子索引，第四和第五个字节是应答式故障码。


### 1.2.3 应答式写

应答式写用于主站写入节点协议表中的对象字典数据，由写指令、写应答（正常）、写应答（异常）组成，详细报文格式如下：

​                                                                      **【表 7】 对象字典写**

| 类型           | **仲裁域**       | **控制域** |      |      |      | **数据域**    |  |          |  |
| -------------- | ---------------- | ---------- | ---- | ---- | ---- | ------------- | ---------- | -------- | ---------------------- |
|                | STID             | RTR        | IDE  | R0   | DLC  | D0            | D1         | D2       | D3~D6       |
| 写指令         | 0x780 + node\_id | 0          | 0    | 0    | 4~7 | CMD_WR        | Index      | SubIndex | 索引映射的数据         |
| 写应答（正常） | 0x7C0 + node\_id | 0          | 0    | 0    | 3    | CMD_WR        | Index      | SubIndex | --                     |
| 写应答（异常） | 0x7C0 + node\_id | 0          | 0    | 0    | 5   | 0x80 + CMD_WR | Index      | SubIndex | 应答式故障码（2bytes） |

**数据域**：主站给节点发送的指令中，数据域第一个字节为CMD_WR (0x02)，第二和第三个字节是待写入数据的索引+子索引。 单次只能写入一个对象。

节点返回的指令中，数据域第一个字节是写命令字CMD_WR，第二和第三个字节是索引+子索引。

当写入非法时，数据域第一个字节是写命令字0x80 + CMD_WR (0x82)，第二和第三个字节是索引+子索引值，第四和第五个字节是应答式故障码。

## 1.3 过程式PDO

### 1.3.1 同步帧

同步帧由主站发出。

**同步帧使用CAN的标准帧格式：**

​                                                                      **【表 9】同步帧标准格式**

| **cob\_id** | **DATA0** | **DATA1** |
| ----------- | --------- | --------- |
| 0x3F        | 0x3C      | 同步计数  |

DATA1是循环同步计数器（0\~255递增），当同步帧使能后，节点监控到同步帧计数器不连续或者相邻两个同步帧抖动较大时将报告通讯异常错误。

### 1.3.2 过程控制帧

过程控制帧用来传输实时的数据，是主站和各节点间通信的最主要传输方式。

过程控制帧包括TxPDO和RxPDO两种类型，TxPDO是由节点发送到主站的过程控制帧，RxPDO是由主站发送到节点的过程控制帧。TxPDO采用触发式，当节点接收到同步帧后，发送TxPDO报文。

不同节点类型的过程控制帧的映射信息独立定义，详情见后文中各关节的过程控制帧定义。

### 1.3.3 紧急报文

当节点出现故障时，节点发送紧急报文，除了主站外，其它节点不处理紧急报文中的故障。

**紧急报文使用CAN的标准帧。**

​                                                                      **【表 10】紧急报文格式**

| **cob\_id**     | **DATA0\~DATA1** |
| --------------- | ---------------- |
| 0x80 + node\_id | 故障代码         |

故障代码在2.2.5中定义。



# 2 节点协议说明

节点本身的信息和控制参数形成了一张二维协议表，在控制芯片的RAM和Flash中各保存一份。在系统上电时，控制芯片从Flash读取协议表到RAM中，在节点运行过程中用户对RAM中的协议表进行读写操作，获取节点状态或对节点进行控制。

二维协议表由索引和子索引组成，索引范围 0x00~0xFF，子索引范围 0x00~0xFF。

### 2.2.2 PDO映射信息说明

#### 映射定义

在索引0x22-0x2F中，定义了4组TxPDO和7组RxPDO，0x2D-0x2F为预留，暂不开放。

每个索引的第一个子索引为映射对象数量，数量0表示本组映射参数不生效。

对象的映射信息是一个32bit的数据，定义如下表所示：

​                                                                      **【表 12】PDO映射信息**

| bit31~bit24    | bit23~bit16      | bit15~bit8 | bit7~bit0            |
| -------------- | ---------------- | ---------- | -------------------- |
| 映射对象的索引 | 映射对象的子索引 | 保留       | 映射对象的数据位长度 |

如需要将在TxPDO0的第二个映射对象映射成实际速度，实际速度的索引是0x20，子索引是0x01，数据是32bit数据。那么TxPDO0 的Subindex = 2处写入0x20010020。

参数是否能被映射需要遵循表中的定义。

协议中TxPDO0，TxPDO1，RxPDO0，RxPDO1，RxPDO2，RxPDO3，RxPDO4，RxPDO5，RxPDO6都有默认参数。 其中TxPDO0上传关节状态，TxPDO1上传MIT模式下的关节状态，RxPDO0用于位置模式的控制，RxPDO1用于速度模式的控制，RxPDO2用于电流模式控制，RxPDO3用于轮廓位置模式控制，RxPDO4用于轮廓速度模式控制，RxPDO5用于轮廓电流模式控制，RxPDO6用于MIT模式控制。

#### CAN波特率——0x000B

协议使用CAN FD 协议标准，CAN FD协议采用独特的“双速率”机制，将一帧数据分为两个阶段：

- **仲裁域(Arbitration Phase)**：负责节点仲裁和帧标识；
- **数据域(Data Phase)**：负责实际数据传输。

**波特率设置后，需保存参数并断电重启后才能生效。**

### 2.2.4  运行模式

#### **2.2.4.1 循环同步位置模式(CSP)**

主站查询关节的工作模式，如果不是工作在位置模式，则切换到位置模式。然后主站按照规定的控制周期和关节进行通讯。每个通讯周期包含主站发送的同步帧、RxPDO（关节停止后不发送）和关节发送的TPDO报文。主站在通讯周期的开始时刻发送同步帧，关节接收到同步帧后会将之前存放在协议表的由RxPDO发送的目标位置更新到位置指令中，然后将相关数据加载到相应的TxPDO报文并回传给主站。主站在接收到TxPDO报文或发送定时到达后，向关节发送RxPDO报文。

**位置模式切换到速度模式或者电流模式时，需要及时更新速度或者电流指令，否则可能会出现异常情况**。

**主站需严格按照同步周期向各关节发送同步帧，关节将按照同步周期对同步帧进行实时监控。若同步周期偏差连续3次超过±20us或单次超过±50us，关节将自动切换至轮廓位置模式（PP）。**

**配置举例**（以关节node\_id=1为例）

**RxPDO0**

| RxPDO0指令描述                       | 帧长度 | 帧ID \| 帧数据             |
| ------------------------------------ | ------ | -------------------------- |
| 主站发送同步帧                       | 2      | 0x3F \| 3C 00              |
| 主站接收TxPDO[获取当前位置，如theta] |        |                            |
| 主站发送【位置指令—theta + 0.1°】    | 6      | 0x201 \| 02 10 xx xx xx xx |
| 主站发送同步帧                       | 2      | 0x3F \| 3C 00              |

**注：每条指令发送后，都需发送同步帧更新控制指令。**

#### **2.2.4.2  循环同步速度模式(CSV)**

主站查询关节的工作模式，如果不是工作在速度模式，则切换到速度模式。然后主站按照规定的控制周期和关节进行通讯。每个通讯周期包含主站发送的同步帧、RxPDO（关节停止后不发送）和关节发送的TxPDO报文。主站在通讯周期的开始时刻发送同步帧，关节接收到同步帧后会将之前存放在协议表的由RxPDO发送的目标速度更新到速度指令中，然后将相关数据加载到相应的TxPDO报文并回传给主站。主站会在接收到TxPDO报文或者RxPDO发送定时到达后向关节发送RxPDO报文。

**速度模式切换到电流模式时，需要及时更新电流指令，否则可能会出现异常情况**。

**配置举例**（以关节node\_id=1为例）

**RxPDO1**

| RxPDO1指令描述                | 帧长度 | 帧ID \| 帧数据             |
| ----------------------------- | ------ | -------------------------- |
| 主站发送【速度指令—10.0 rpm】 | 6      | 0x241 \| 02 20 00 00 20 41 |
| 主站发送同步帧                | 2      | 0x3F \| 3C 00              |

**注：每条指令发送后，都需发送同步帧更新控制指令。**

#### 2.2.4.7 **混合控制模式**(MIT) 

**混合控制模式**是一种用于电机控制的混合集成扭矩控制模式，能够实现对力矩、位置和速度的综合控制。其核心思想是通过刚度系数和阻尼系数的调节，结合前馈力矩，生成目标力矩，从而实现对电机力矩的控制，公式如下：

​                                   **T_ref = kp * (p_des - θ) + kd * (v_des - dθ) + t_ff**

- **T_ref**：目标力矩（单位：N·m）；
- **kp**：刚度系数；
- **kd**：阻尼系数；
- **p_des**：期望位置（单位：rad）；
- **θ**：实际位置（单位：rad）；
- **v_des**：期望速度（单位：rad/s）；
- **dθ**：实际速度（单位：rad/s）；
- **t_ff**：前馈力矩。

**配置举例**（以关节node\_id=1为例）

**RxPDO6**

| RxPDO6指令描述                                               | 帧长度 | 帧ID \| 帧数据                                               |
| ------------------------------------------------------------ | ------ | ------------------------------------------------------------ |
| 主站发送【期望位置——1.0rad】<br>               【期望速度——0.5rad/s】<br/>               【前馈力矩——0.5 N·m】<br/>               【刚度系数——1.0 N·m/rad】<br/>               【阻尼系数——1.0 N·m·s/rad】 | 24     | 0x381 \| 02 70 00 00 80 3F <br>                          00 00 00 3F <br/>                          00 00 00 3F <br/>                          00 00 80 3F <br/>                          00 00 80 3F<br>                          00 00 |

#### 2.2.4.8 停机方式

- 故障停机

  发生故障和警告时，关节自动进入故障停机状态，通过关闭抱闸和停止功率模块输出的方式实现故障停机，关节处于自由运行状态。

- 紧急停机

  控制字的急停控制位为1时，关节进入紧急停机状态。

**停机过程中，关节不响应伺服指令。**

### 2.2.6 警告代码定义

警告代码（对象字典：0x0009）以16bit的编码方式上传。出现警告代码后，关节不会主动停机，但应关注警告产生的原因，必要时用户可主动停机检查。

警告代码代表的含义如下：

​                                                                      **【表 20】警告代码定义**

| 警告代码（hex） | 警告名称          | 警告产生的原因                       |
| --------------- | ----------------- | ------------------------------------ |
| 0x0000          | 无警告            | -                                    |
| 0x2101          | PCB高温           | PCB温度超过警告阈值。                |
| 0x2102          | 电机高温          | 电机温度超过警告阈值。               |
| 0x2103          | 减速器高温        | 电机减速器温度超过警告阈值。         |
| 0x2201          | 相电流过载        | 电机相电流超过额定负载。             |
| 0x2301          | 速度过高          | 电机当前速度超过额定速度。           |
| 0x2401          | 位置超过限制值    | 电机当前位置超过设定的限制值。       |
| 0x2601          | flash擦除次数过高 | 本次上电后，flash擦写次数超过100次。 |
